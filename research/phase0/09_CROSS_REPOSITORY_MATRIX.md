# Cross-Repository Subsystem Matrix

## Scope and decision rules

This matrix synthesizes the implementation audits in `01`-`08` and the policy, provenance, architecture, skills, local-model, security, reuse, and conflict reports in this directory. "Best reference" means the strongest checked implementation or invariant for the named subsystem; it does **not** mean that its source is legally or technically suitable for direct import.

The normalized implementation/source inspection ledger is **609 files**: OpenClaw **220**, OpenDroid **101**, AndyClaw **118**, Hermes **58**, MobileRun **57**, AnyClaw **37**, and AirLLM **18**. The broader per-repository material-artifact ledgers total **713** when tests, build/license/config and other report-specific evidence are retained: **256**, **116**, **134**, **62**, **72**, **45**, and **28**, respectively. The matrix uses the normalized figure for cross-repository scale and the broader figure only as audit-depth context.

Exact path aliases used below:

- `[OC]` = `E:\Projects\Eco_reference\openclaw`
- `[OD]` = `E:\Projects\Eco_reference\opendroid`
- `[AC]` = `E:\Projects\Eco_reference\AndyClaw`
- `[HA]` = `E:\Projects\Eco_reference\hermes-agent`
- `[MR]` = `E:\Projects\Eco_reference\mobilerun-main`
- `[YC]` = `E:\Projects\Eco_reference\anyclaw`
- `[AL]` = `E:\Projects\Eco_reference\airllm`

Within an evidence cell, a comma-separated sibling filename inherits the full directory of the immediately preceding aliased path; `::` introduces the exact class, type, function, or method symbol rather than forming part of the filesystem path.

Every matrix row has exactly one disposition label:

- `REUSE`: a narrow implementation can plausibly be used substantially as written after attribution, SBOM, and test review.
- `ADAPT`: permissively licensed code is a useful implementation seed, but Kinetic APIs, policy, lifecycle, or behavior must change.
- `PORT_SEMANTICS`: preserve contracts, state transitions, failure rules, and tests; write new Kotlin rather than translate source line by line.
- `CLEAN_ROOM`: independently specify and implement because GPL, provenance, or safety makes adaptation inappropriate.
- `REFERENCE_ONLY`: retain for research or test inspiration, not as product implementation.
- `REJECT`: exclude the implementation and its behavior from Kinetic Core.

"Kotlin portability" estimates the engineering transfer, not license permission: **High** means a Kotlin/Android or small pure-logic seed exists; **Medium** means the semantics are clear but require a Kotlin rewrite; **Low** means only a concept or research hypothesis transfers. Dependency burden includes Android/platform services, persistence, native runtimes, provider SDKs, and policy infrastructure.

## Hard reuse, provenance, and Play constraints

1. **Source reuse versus conceptual reuse:** only rows marked `ADAPT` identify a plausible permissive code/test seed, and even those require path-level provenance, retained notices, an SBOM, dependency review, and behavior tests. `PORT_SEMANTICS` means a fresh Kotlin implementation from documented invariants and conformance tests. `CLEAN_ROOM` means an independently authored specification and implementation with no source translation.
2. **GPL boundary:** AndyClaw is GPL-3.0. Its registry/search, memory, GGUF wrapper, executor, heartbeat, and extension code are concept/negative-test evidence only unless Kinetic deliberately accepts GPL-compatible distribution. The matrix does not authorize copying it. Its active raw Binder extension wire also conflicts with its stub AIDL wire, so there is no stable protocol to adopt.
3. **Opaque and unresolved artifacts:** do not ship `[AC]\llamatik\llamatik.aar`, `[AC]\tinfoil-bridge\tinfoil-bridge.aar`, `[AC]\app\src\main\assets\ggml-base.en-q5_1.bin`, or the vendored Whisper tree without independently recovered source, revision, license/notices, model card, digest, ABI, and SBOM. Repository GPL does not establish third-party binary/model provenance.
4. **MobileRun provenance:** `[MR]` has no `.git` metadata, and decisive `mobilerun-core-local`/Portal behavior is external. Its algorithms/tests may inform a fresh specification; implementation copying remains blocked until the exact revision and dependency licenses are pinned.
5. **Skill provenance:** root MIT does not blanket-license remotely installed packages or every bundled skill. In particular, Hermes productivity skill subtrees carrying restrictive `LICENSE.txt` terms are rejected for copying or transformation. Every imported skill needs its own author/source/version/digest/signature/license record.
6. **Play artifact boundary:** general LLM-planned Accessibility, `MANAGE_EXTERNAL_STORAGE`, broad package visibility, package installation, shell/Python/Node/BeanShell/Termux, arbitrary browser evaluation, root/Shizuku, remote DEX/JAR/SO, and persistent-daemon assumptions must not enter Play Core. Compile Play, advanced, and optional OEM/system capability providers from distinct source/manifest allowlists.
7. **App integration policy:** AppFunctions is a strategic but preview/availability-dependent provider, not the domain model. Use intents, pickers, SAF grants, app-owned APIs, and explicitly signed IPC where appropriate. Discovery, runtime permission, and user approval are separate gates.
8. **Model and native provenance:** app source licenses do not license model weights, tokenizers, native engines, hosted APIs, or training data. Every engine/model pair needs immutable revision, hashes/signature, license acceptance, compatibility, storage/RAM/thermal facts, revocation, and deletion support.
9. **AirLLM boundary:** `[AL]\air_llm\airllm\airllm_base.py::AirLLMBaseModel/_install_streaming_hooks/_setup_expert_streaming` is an Apache-2.0 research comparator, not either Local LLM candidate. PyTorch/Transformers/Accelerate/CUDA/bitsandbytes or Darwin MLX, repeated weight I/O, remote model code, and unmeasured mobile energy/thermal cost make direct Android porting unjustified. Retain only the hypothesis of an explicit measured residency/prefetch plan for a later benchmark spike.
10. **AnyClaw executable boundary:** the MIT descriptor and MCP normalization ideas are usable, but `[YC]\internal\adapter\cli.go::CLIAdapter.Execute`, `script.go::ScriptAdapter.Execute`, browser `evaluate`, the unauthenticated loopback daemon, and mutable unsigned registry/install flow are rejected from Kinetic Core.

## Cross-repository architecture conclusion

No repository should be used as Kinetic's base. The clean composition is:

- permissive Kotlin adaptation from OpenClaw Android for the capability edge, durable outbox/transport lifecycle, voice, UI, and flavor separation;
- permissive Kotlin adaptation from OpenDroid for provider retry, secrets, model download/storage, selected Android handlers, schema/test seeds, and permission UX;
- native semantic ports of OpenClaw's agent/task/session/cron/security invariants and Hermes' provider/context/memory/skill boundaries;
- native semantic ports of MobileRun's planner and snapshot/coordinate contracts after provenance recovery;
- a constrained, signed Skill IR informed by Hermes/OpenClaw and the safe subset of AnyClaw's descriptor/pipeline vocabulary;
- clean-room use of AndyClaw's hybrid-memory, extension, and GGUF concepts only; and
- AirLLM retained solely as a benchmark hypothesis.

The governing invariant is that the model proposes; a durable Kotlin kernel, deterministic policy broker, and typed executor authorize, journal, execute, and reconcile.
