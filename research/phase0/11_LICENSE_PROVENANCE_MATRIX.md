# License Provenance Matrix

## Rules used in this audit

This is an engineering provenance assessment, not legal advice.

1. A repository-level license is only the starting point. A nearer subdirectory license, file header, vendored archive, generated asset, model license, API terms, or copied upstream notice can override or add obligations.
2. “Open source” never means “safe to copy without conditions.” MIT requires preservation of its notice; Apache-2.0 adds notice/modified-file/patent conditions; GPL-3.0 has source and reciprocal licensing consequences for derivative distribution.
3. Protocol behavior and independently reimplemented interfaces may be separable from source copying. Literal AIDL/schema/constants/text can still be copyrighted; use a clean-room specification where the license is incompatible.
4. Dependencies, model weights and remotely hosted skills are not relicensed by an application's root license.
5. No source is to be copied during Phase 0. `REUSE`/`ADAPT` means a future phase may do so only with a provenance record, retained notices, dependency/SBOM review and tests.

Candidate paths are repository-relative to the repository named in each row. In particular, AndyClaw `app/...` expands to `Eco_reference/AndyClaw/app/src/main/java/org/ethereumphone/andyclaw/...`, AndyClaw `AndyClaw/...` expands to `Eco_reference/AndyClaw/AndyClaw/src/main/java/org/ethereumphone/andyclaw/...`, and OpenDroid `app/...` expands to `Eco_reference/opendroid/app/src/main/java/com/opendroid/ai/...`.

## File-level header findings

- Candidate OpenClaw, OpenDroid, AndyClaw, MobileRun, AirLLM and AnyClaw implementation files sampled above generally carry no SPDX or explicit file header. Their license mapping therefore depends on repository/subtree placement.
- `Eco_reference/hermes-agent/plugins/security-guidance/patterns.py` is the clear exception: its docstring explicitly records Anthropic upstream, Apache-2.0 and commit `0bde168`, and says the pattern data is verbatim.
- `Eco_reference/hermes-agent/plugins/security-guidance/NOTICE` corroborates that only `patterns.py` is upstream Apache while Hermes glue is MIT.
- `Eco_reference/hermes-agent/skills/productivity/*/LICENSE.txt` demonstrably conflicts with a blanket “root MIT” assumption. These materials are rejected for copying.
- `Eco_reference/AndyClaw/app/src/main/cpp/whisper/whisper.cpp` and `ggml.c` have no license header in their opening content, while `CMakeLists.txt` only states they came from “whisper.cpp / FUTO keyboard.” That is insufficient provenance for distribution.
- `Eco_reference/airllm/training/qlora.py`, `rlhf/qlora_dpo.py`, and `anima_100k/longer_training.py` say they are MIT-licensed in comments but direct readers to a root license that is actually Apache-2.0. The inconsistency requires origin tracing; none is a Kinetic candidate.
- OpenClaw's package-level gateway license files exactly repeat the Foundation MIT grant, reducing ambiguity for those contract packages.

## Required provenance process for future phases

For every adapted file or test vector, record: local repository + audited commit, original upstream URL/commit, exact source path, nearest license, file headers, substantial-adaptation ancestry, modifications, dependency/model licenses, notice text, and the Kinetic destination path. CI should generate an SBOM and fail release builds when a bundled native library/model/skill lacks a digest, origin, version and license decision.

## Hard decisions

- **Do not copy AndyClaw source** unless Kinetic deliberately accepts GPL-3.0-compatible distribution; default to clean-room reimplementation/protocol interoperability.
- **Do not copy Hermes productivity skills** carrying restrictive `LICENSE.txt` terms.
- **Do not ship AndyClaw's `llamatik.aar` or vendored Whisper tree** from this checkout.
- **Do not copy MobileRun implementation until its missing commit provenance is recovered.** Semantic study and independently designed tests are acceptable in the meantime.
- OpenClaw MIT contracts/native Android components and OpenDroid Apache-2.0 Android components are the principal future source-reuse pools, subject to per-file and dependency review.
